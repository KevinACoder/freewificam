# components/linuxkpi/skbuff - divergences

Deviations of the pool body (`skbuff_pool.c`) from its fact source
(`components/skbuff/`, the verbatim TizenRT/Realtek osdep unit) and from the
imported face. One row per convergence step; the source itself is never edited.

| # | Where | Change from the fact source | Reason | Round |
|---|---|---|---|---|
| 1 | free-slot linkage | The two free lists (`wrapper_skbbuf_list`, `skbdata_list`; source `:24,45`) are dropped. Hand-out scans the slot array for the **lowest-index free slot**, where "free" is the state the contract already tracks: the header slot's release marker (`_gen`, a new slot any non-zero value, `LKPI_SKB_FREED_MAGIC` when released, 0 when never handed out) and the data slot's reference count (0 = free, otherwise owned). | A second linkage can only disagree with the state the contract reads, and the lowest-index policy is the one the contract cells freeze (`tests/host/skbuff-allocation-free-stress/cases.c:302`: a released slot "must be the one reissued"). With the scan in place the lists would be a redundant index an operation could forget to update; the FIFO order the lists gave is not observable through the face. Source `:73-103` (`get_buf_from_poll`/`release_buf_to_poll`) is replaced by the scan and the counter updates. | pool-body R1 |
| 2 | geometry at runtime | The compiled `CONFIG_LKPI_SKB_*` macros are **upper bounds**; `lkpi_skb_pool_configure()` selects the geometry in force at run time within them (default = the macros). The source's sizes are already variables (`_WEAK int max_local_skb_num` / `max_skb_buf_num`, source `:15-22,37`). | The Gate 1 contract harness runs one scenario geometry per cell in one binary (`cases.c:187-195` pins a 4x4x64 pool) and needs the production body to accept it; without this the body could only serve one geometry per binary and the cell's scenario would stop being exercisable against the shipped code. Host-only in effect: a board build never calls it. | pool-body R1 |
| 3 | slot state: release marker and tombstones | A released header slot is marked by `_gen = LKPI_SKB_FREED_MAGIC` and its fields are zeroed (`slot_mark_released`); heap-backed headers go to a small tombstone ring at release (`tomb[]`). The source distinguishes states by list membership plus `dyalloc_flag`/`busy`/`no_free` fields (source `:26-30,143-263`). | The contract requires states to be observable through the public fields (the harness reads `_gen` and writes through released pointers), and requires a double free to be *named* rather than reaching the allocator: with the marker plus the ring, a second release is refused with `double_free`, a foreign pointer with `stray_free`, and a geometry op on a released slot with `uaf_write`. The source's `busy`/`no_free` bus-protocol fields have no consumer in this repository and are not carried. | pool-body R1 |
| 4 | linear-buffer slab for heap fallbacks | Oversize requests and exhausted pools fall back to the heap through `lkpi_spl_malloc` in one block that carries an 8-byte reference word in front of the payload, so a heap-backed buffer shares and returns by the same reference discipline as a pool data slot (one code path for `buf_ref_inc`/`buf_ref_put`). | The source's `rtw_zmalloc` fallback (source `:173`) has no reference discipline - `skb_clone` could not copy it and `kfree_skb` frees it unconditionally (source `:218,252-254`). This project's clone path is real (the driver clones aggregated RX frames) and the statistics the contract asserts (`dyalloc_live`) need the lifetime to be one mechanism. | pool-body R1 |
| 5 | per-data-slot alignment and stride | A data slot is a fixed struct `{ref, pad, buf[CONFIG_LKPI_SKB_DATA_BUF_SZ]}` with the payload 64-byte aligned; the compile-time assertions pin both the alignment and that the stride contains the payload. The source aligns the *data array* and comments that "starting address must be aligned by 32 bytes for km4 cache" (source `:28-35`). | On this target the alignment of a buffer handed to a DMA path is a fact a consumer may rely on (the USB backend's staging decision reads it), and a per-slot guarantee is stronger than an array-base guarantee. The fixed member (not a flexible array) is required: an element with a flexible payload has the stride of its header, so every slot's payload would land on the next slot's header. Both are compile-time facts, not comments. | pool-body R1 |
| 6 | diagnostics | The counters and refusal names are this project's (`skbuff_pool.h:85-122`: `double_free`, `stray_free`, `uaf_write`, `fence_bad`, `dyalloc_live`, `dyalloc_oversize`, `slot_overflow`, `data_overflow`, `alloc_fail`), plus `lkpi_skb_fence_scan` (a scan of released slots' canonical shape and their free buffers' fence bytes) and `lkpi_skb_uaf_hit`. The source's `skbuff_used_num`/`max_skbdata_used_num` shape is kept as `skb_used`/`skb_high`/`data_used`/`data_high`; its `CONFIG_TRACE_SKB` snapshot machinery (source `:273-459,403-457`) is not carried. | The counters are the contract's observation face (asserted by the judge and the streams); the trace machinery depends on a per-frame tag array and a console that this repository does not have, and the same ground is covered by the by-name refusals plus the fence scan. | pool-body R1 |
| 7 | critical sections | Every mutating entry takes the face's platform hook pair (`lkpi_spl_irqsave`/`irqrestore`, `skbuff_pool.h:129-130`), whose target bodies are the port's interrupt-mask sections; the public queue operations additionally take the queue's own lock (`linuxkpi_core.h:1811-1817`), and the raw `__` forms take nothing (the caller-locks contract). The source calls `save_and_cli`/`restore_flags` around single list operations only (source `:56-58,152-155,176-177,187-189,240-262`). | The face declares the hooks as the pool's only platform binding and the public queue operations as internally locked; a caller (a driver's completion context) relies on the public forms being safe from any thread, which is exactly what the hook pair provides on a single-core target. | pool-body R1 |
| 8 | headers | The body's includes are the Linux API face (`linuxkpi_core.h`, `include/linux/skbuff.h`) and, on the target only, the port facade header (`os/cmsis2/cmsis2.h`, behind `LKPI_SKB_POOL_NO_TARGET_HOOKS`). The source includes its board's `drv_types.h` and wrapper header. | This component compiles against the Linux API face by construction (that is what its consumers include); the facade include is guarded so a host build that supplies its own hooks does not need the port tree. | pool-body R1 |
