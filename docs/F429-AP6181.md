# AP6181 (BCM43362) on the STM32F429 Challenger V2

This is the first-party port of the module's own driver: Cypress **WICED WWD**
for the **BCM43362** (the chip on the onboard AP6181), running on the F429 bare
metal under FreeRTOS. It is **not** the Linux compatibility road: nothing in
this driver links `linuxkpi`, `mac80211` or `cfg80211`, and the image gate
below proves it.

The four rungs are separate cases with separate profiles, each one a relay
cold boot away:

| Rung | Case | Profile | Pass line |
|---|---|---|---|
| attach | `ap6181_attach` | `stm32f429-ap6181-attach` | `ap6181: PASS ATTACH` |
| scan | `ap6181_scan` | `stm32f429-ap6181-scan` | `ap6181: PASS SCAN` |
| STA join | `ap6181_join` | `stm32f429-ap6181-join` | `ap6181: PASS JOIN` |
| data plane | `ap6181_data` | `stm32f429-ap6181-data` | `ap6181: PASS DATA` |
| throughput (report only) | `ap6181_tput` | `stm32f429-ap6181-tput` | `ap6181: PASS TPUT` |

## What is vendor and what is first-party

The WWD core is Cypress source under the WICED license. It is not tracked in
this repository: `tools/build/wiced-tree.py` copies the pinned subset from an
external WICED tree (the pin is the version string and commit id in
`WiFi_SDK/version.txt`) into `wireless-drivers/ap6181/vendor/`, which is
git-ignored, and records a sha256 manifest so a working tree is reproducible.
See `PROVENANCE.md` for the pin and `LICENSES.md` for what the license allows.

Vendor, compiled unchanged:

- `wwd_SDIO.c` — the whole SDIO host: enumeration, clock and bus-width setup,
  the transfer engine, the SDIO and DMA interrupt handlers, the OOB line.
- `peripherals/platform_gpio.c`, `peripherals/platform_mcu_powersave.c` — the
  platform's GPIO and powersave layers it stands on.
- the StdPeriph SDIO/GPIO/RCC/SYSCFG/EXTI/MISC drivers and the CMSIS device
  headers, with `STM32F429_439xx` and `USE_STDPERIPH_DRIVER` coming from the
  profile's Kconfig through `ports/f429/wiced_kconfig.h`.

First-party (`ports/f429/`):

- `wwd_platform.c` — the board face: WL_REG_ON on PB13, the rail settle, the
  MAC, the 32 kHz question (this board has no such path).
- `wwd_rtos.c` — WWD's RTOS interface on FreeRTOS.
- `wwd_buffer.c` — every WWD buffer is an lwIP pbuf with the driver's headroom.
  `wwd_network.c` — the netif seam and the receive hand-off.
- `wiced_pins.c` — the module's pin table in the vendor's `platform_gpio_t`
  vocabulary (PB13 reset, PA0 OOB, PC8-PC11/PC12/PD2 SDIO).
- `wiced_kconfig.h` — the profile's Kconfig switches as the vendor sources see
  them (bootloader off, PMK in firmware, the OOB and log options).
- `wiced_console.c` — the vendor driver's `printf` on the board console, only
  when the profile asks for the driver log.

The vendor's own `wwd_buffer.c`/`wwd_network.c` are written against the WICED
fork of lwIP (`PBUF_POOL_RX/TX`, `struct pbuf::type`), and its `wwd_rtos.c`
wants the old `stackmacros.h`; those three, and the platform face, are the
port's seam and stay first-party.

## Build

```
./make.rtos image PROFILE=stm32f429-ap6181-attach
./make.rtos image PROFILE=stm32f429-ap6181-scan
./make.rtos image PROFILE=stm32f429-ap6181-join
./make.rtos image PROFILE=stm32f429-ap6181-data
./make.rtos image PROFILE=stm32f429-ap6181-tput
```

Each image carries one case. `make -C tests/board/rtos/build PROFILE=<p>
wiced-image-gate` rebuilds and proves the image has no
`linuxkpi`/`mac80211`/`cfg80211`/`brcmfmac` symbol (the linker script's empty
`__lkpi_*` section boundaries are not symbols and are allowed).

`CONFIG_WICED_AP6181_LOG=y` adds WWD's own `WPRINT_WWD_*` output on the
console; it is off in the delivered profiles.

## The console, rung by rung

```
ap6181: stage=attach
ap6181: fw bytes=210624
ap6181: wifi_on rc=0
ap6181: mac=9c:b8:b4:74:5f:e1
ap6181: PASS ATTACH
```

```
ap6181: stage=scan
ap6181: scan start rc=0
ap6181: scan done=1 n=18 waited=100ms
ap6181: bss0 ssid=... bssid=... ch=1 rssi=-48
...
ap6181: PASS SCAN
```

```
ap6181: stage=join
ap6181: join rc=0
ap6181: link wait=700ms
ap6181: bssid=1c:a7:70:de:29:a1
ap6181: rssi=-18
ap6181: PASS JOIN
```

```
ap6181: stage=data
ap6181: netif ip=192.168.99.2
ap6181: icmp sent=20 recv=20 tx=21 buffail=0
ap6181: PASS DATA
```

`wwd_wifi_join()` returns when the request is accepted; the link comes up with
the association event, so the join case waits for
`wwd_wifi_is_ready_to_transceive()` before it reads the BSSID.

## Throughput (report only)

The throughput case joins the bench AP, takes `192.168.99.2/24`, and runs two
TCP phases of 4 MiB against `192.168.99.1`: TX pushes bytes into a sink, RX
pulls them from a source. There is no pass threshold; the case fails only if a
phase cannot run at all.

Measured over the bench AP (channel 5, open, 20 MHz), two cold boots:

| Phase | Run 1 | Run 2 | Peer's own count |
|---|---|---|---|
| TCP TX (board to AP) | 6.06 Mbit/s | 6.33 Mbit/s | 6.06 / 6.33 |
| TCP RX (AP to board) | 9.83 Mbit/s | 10.15 Mbit/s | 9.91 / 10.22 |

The numbers are the whole picture on this board: a single 168 MHz Cortex-M4
running the driver, lwIP and the application, with the SDIO link at 24 MHz
4-bit and the radio on 802.11n HT20. They are not a comparison against any
other host and are not carried to any other platform.

## Two seams that bite

- **One lwIP init per image.** The attach/scan/join shapes call
  `ap6181_lwip_core_init()`; the data shape calls `ap6181_lwip_stack_start()`,
  which brings the TCP/IP thread up as well. Calling both initialises the core
  twice and lwIP asserts `netif already added`.
- **Headroom.** The driver prepends its SDPCM/BDC header into the pbuf it is
  handed, so `lwipopts.h` sets `PBUF_LINK_ENCAPSULATION_HLEN` to 64, matching
  the driver's own headroom constant. Without it every transmit is dropped with
  "Unable to adjust header space".

## Bench

The radio sits on the lab AP (`labwifi-ar-ht20s`, channel 5, open,
`192.168.99.1`); the board takes `192.168.99.2/24` and the data case pings the
AP twenty times. The AP's own capture shows the twenty echo requests and the
twenty replies, so the rung is the air, not just the stack's counters.
